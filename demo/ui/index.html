What is real, what is simulated, and what this check cannot prove

Source loading, Semgrep scans, results, run durations, and activity events are real and local. Repository context is a demonstration, not a GitHub workflow. No checks, comments, or code changes are sent to GitHub.

Only bundled samples can be scanned. Six authored, hash-pinned fixtures execute in bounded child processes using synthetic services only. Static scanner fixtures are never executed. No dependency is installed, external alert sent, or network request made by a fixture. Four categories have narrow demo rules for debug mode, TLS verification, SQL concatenation and YAML loading. Six categories have actual behavioral assertions against synthetic adapters. A pass proves only those lab assertions, not the behavior of real databases, identity providers, build pipelines or monitoring systems. They do not detect every variant or prove input validation correct. A scan pass means no finding under its rule; a behavioral pass means the stated lab assertions held. Neither proves general security. The production webhook’s existing rules are unchanged.

This process is not an operating-system sandbox. Production use still awaits Linux container isolation tests and resolution of five scanner dependency advisories. No secrets or arbitrary repository uploads are accepted.
